## ნიკოდიმოსის განმარტებები (კომენტარები)

- კანონის ქვეშ ღილაკი „▸ ნიკოდიმოსის განმარტება“ — დაჭერისას კომენტარი იხსნება (ნიკოდიმოსის თარგმანი, განმარტება, მითითებული კანონების ბმულები, ტომი/გვერდი).
- `/councils/[id]/commentary` — კრების ყველა განმარტება ერთ გვერდზე.
- დამატებითი დოკუმენტები 42–44 (იოანე მარხვისმოყვარე, ნიკეფორე, ნიკოლოზი) ნიკოდიმოსის გამოცემიდან.
- კომენტარი ინლაინ ჩანს იქ, სადაც ორი თარგმანის ნუმერაცია ემთხვევა (`ALIGNED` build_data.py-ში). კართაგენისა და ზოგი ეპისტოლეს განმარტება მხოლოდ განმარტებების გვერდზეა.

## გაშვება

```bash
npm install
cp .env.example .env.local     # შეავსეთ LLM_* ცვლადები (ქვემოთ)
npm run dev                    # http://localhost:3000
```

AI მოდელის გარეშეც მუშაობს ყველაფერი; ასისტენტი მხოლოდ მოძებნილ კანონებსა და განმარტებებს აჩვენებს.

## უფასო AI მოდელი (ლოკალურად, გასაღების გარეშე)

1. დააინსტალირეთ [Ollama](https://ollama.com/download) და გახსენით (ფონზე უნდა მუშაობდეს).
2. პროექტის საქაღალდეში: `npm run setup:ai`. სკრიპტი RAM-ის მიხედვით ირჩევს Gemma 3-ს (4b / 12b / 27b), ჩამოტვირთავს მას და ააწყობს მოდელს `kanoni-gemma`-ს სახელით.
3. `npm run dev` და გახსენით `/assistant`. ასისტენტი ლოკალურ მოდელს ავტომატურად აღმოაჩენს.

რჩევა: 4b მოდელი სწრაფია, მაგრამ ქართულად საშუალოდ წერს. 12b ან უფრო დიდი აგრძნობინებთ განსხვავებას (საჭიროა დაახლ. 16 GB RAM). საუკეთესო ქართულისთვის გამოიყენეთ ქვემოთ აღწერილი Gemini API (უფასო ტარიფი).

## AI მოდელის მიერთება (ღრუბლოვანი API)

ასისტენტი ნებისმიერ OpenAI-თავსებად API-ს იყენებს (`/chat/completions`, ნაკადური პასუხი). `.env.local`:

```
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai   # Gemini (უფასო ტარიფი)
LLM_API_KEY=...
LLM_MODEL=gemini-2.5-flash
```

სხვა მაგალითები (Groq, OpenRouter, Ollama, Azure OpenAI) `.env.example`-შია. Ollama-თი სრულად ლოკალურად მუშაობს, მაგრამ ქართულისთვის დიდი მოდელი სჭირდება (პატარა მოდელები ქართულად სუსტია).

## როგორ მუშაობს

1. **მონაცემები** (`scripts/build_data.py`): ძველი აპის HTML-ები (`source/legacy-assets`) გასუფთავდა და კანონებს მიეცათ ანკერები (`#k35`). ნიკოდიმოსის ორი PDF-ის ტექსტური ფენა (OCR) დაიყო კრებებად და კანონებად, გასუფთავდა სათაურები და გადატანის დეფისები. შედეგი: `data/` (დაახლ. 3 MB).
2. **ძიება** (`lib/search.ts`): BM25 სიტყვის 6-ასოიან პრეფიქსებზე და 4-ასოიან n-გრამებზე, ამიტომ „ქორწინება“ პოულობს „დაქორწინდა“-ს. „ლაოდიკიის 35-ე კანონი“ ტიპის პირდაპირი მითითებები ცალკე ამოიცნობა. თემატური სარჩევის დამთხვევა მასში მითითებულ კანონებს აძლიერებს.
3. **პასუხი** (`app/api/chat/route.ts`): ზედა შედეგებიდან იქმნება წყაროების ჯგუფი (კანონის ტექსტი + ნიკოდიმოსის განმარტება), მოდელი პასუხობს მხოლოდ მათზე და ყოველ დებულებას `[N]` მითითებით ამოწმებს.

## მონაცემების თავიდან აგება

```bash
pip install beautifulsoup4 lxml   # და საჭიროა poppler (pdftotext)
python3 scripts/build_data.py --pdf1 <ტომი I.pdf> --pdf2 <ტომი II.pdf>
```

PDF-ების სექციები (`VOL1`, `VOL2` სკრიპტში) გვერდების დიაპაზონებით არის აღწერილი. თუ სხვა გამოცემას გამოიყენებთ, ეს ცხრილი უნდა შეიცვალოს. PDF-ის გარეშე გაშვებისას განმარტებები `chunks.json.gz`-ში აღარ მოხვდება.

## ცნობილი შეზღუდვები

- განმარტებების ტექსტი OCR-ია: ზოგჯერ ასოები არეულია. კანონების ნუმერაცია ავტომატურად აღდგება (გამოტოვებული სათაურები იგულისხმება თანმიმდევრობით), მაგრამ ცალკეულ კანონზე განმარტება შეიძლება მეზობელს მიეკუთვნოს.
- კართაგენისა და ორგზისის კრებების საზღვარი PDF-ში მიახლოებითია (გვ. 248).
- ძიება ლექსიკურია (სიტყვებზე დაფუძნებული). სინონიმებს LLM-ით საძიებო სიტყვების გაფართოება ასწორებს (`QUERY_REWRITE`). შემდეგი ნაბიჯი შეიძლება იყოს ემბედინგები (`bge-m3`).
- განმარტებების ტექსტი დაცული გამოცემიდან არის აღებული. საჯარო გამოქვეყნებამდე გადაამოწმეთ უფლებები.

## საიტად გამოქვეყნება (AI-ით)

ლოკალური Ollama ჰოსტინგზე არ მუშაობს, ამიტომ საიტზე უფასო ღრუბლოვანი მოდელი გამოიყენეთ. გასაღები ინახება მხოლოდ სერვერზე (გარემოს ცვლადში), ვიზიტორებს არაფერი სჭირდებათ.

1. აიღეთ უფასო გასაღები: [Google AI Studio](https://aistudio.google.com/apikey) (ძირითადი) და სურვილისამებრ [Groq](https://console.groq.com/keys) (სარეზერვო).
2. ატვირთეთ პროექტი GitHub-ზე (`.env.local` არ ატვირთოთ, ის უკვე `.gitignore`-შია).
3. [vercel.com](https://vercel.com) → **Add New → Project** → აირჩიეთ რეპოზიტორია.
4. **Environment Variables**-ში დაამატეთ:

   | სახელი | მნიშვნელობა |
   |---|---|
   | `LLM_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta/openai` |
   | `LLM_API_KEY` | თქვენი Gemini გასაღები |
   | `LLM_MODEL` | `gemini-2.5-flash` |
   | `LLM2_BASE_URL` | `https://api.groq.com/openai/v1` (არასავალდებულო) |
   | `LLM2_API_KEY` | Groq გასაღები (არასავალდებულო) |
   | `LLM2_MODEL` | `llama-3.1-8b-instant` (არასავალდებულო) |

5. **Deploy**. შემდეგ ცვლადების შეცვლისას საჭიროა Redeploy.

უფასო კვოტის დასაცავად ჩართულია ლიმიტები: `RATE_LIMIT_PER_10MIN` (ნაგულისხმევი 30 ერთ IP-ზე) და `DAILY_LIMIT` (ნაგულისხმევი 400 დღეში). როცა ძირითადი პროვაიდერის უფასო ლიმიტი ამოიწურება, ასისტენტი ავტომატურად სარეზერვოზე გადადის. ორივეს ამოწურვისას ძიება და მკითხველი ჩვეულებრივ მუშაობს.

სხვა ჰოსტინგზე (Netlify, Railway, საკუთარი სერვერი) იგივე ცვლადებია საჭირო; `npm run build && npm start`. `data/` ფაილები (დაახლ. 3 MB) პროექტთან ერთად უნდა აიტვირთოს.
